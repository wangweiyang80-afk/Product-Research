# Product Research — 品类调研 SOP

跨境电商新品类 / 新产品「**是否立项、如何切入**」的市场调研标准作业流程。

一句话总纲：**调研不是查资料，是回答一个决策问题。** 一份调研合格的唯一标准是看完能拍板——字数、来源数、页数都不是标准。

---

## 这套 SOP 解决什么问题

常见的品类调研会在三个地方塌掉，这套流程针对性地堵住它们：

| 常见塌点 | 这套 SOP 的对策 |
|---|---|
| 资料堆了很多，但拍不了板 | 第 0 步先把委托钉成「决策问题 + 拍板人 + 否决变量」；每张比对表强制带「对我们的含义」列 |
| 需求和竞争做得很深，**但算不出一个毛利率** | 把单位经济提成一级维度，立项前必须交单位经济表，允许给区间、**不允许整张缺失** |
| 数据全抓自一天，却写出「某价位带增长最慢」 | 时序基线：抓完当天固定关键词 / 字段 / 脚本，≥30 天后原样复跑；两次没跑完之前，「增长 / 下滑」一律降级为「占比 / 结构」 |
| 表面数字当真就下结论 | 去伪清单 8 项逐项过，过不了的数字降级或剔除 |
| 结论全来自二手数据，没碰过实物 | 最小实证投入列为结项门槛：买竞品实物、工厂索正式报价、小额流量测试 |

---

## 怎么用

1. **开工前通读** [`品类调研SOP.md`](品类调研SOP.md)，先写第 0 步那三行。写不出来就先问委托人，不要开始查资料。
2. 按 **§2 七维** 并行拆任务，每维对应一个决策问题、各有必出产物。
3. 按 **§3 四轮节奏**（广度 → 深度 → 交叉 → 穷举）推进。每轮由上一轮「最不确定、最能否决」的那一项驱动，不是平均加码。
4. 写报告直接套 [`templates/`](templates/) 里的模板。
5. 结项前用 [`templates/结项门槛.md`](templates/结项门槛.md) 逐项打勾。**全部打勾才算完成**，任一项没勾，状态是「进行中」而不是「待审」。

## 几个核心主张

**R3 的「交叉对撞」是整套流程最值钱的一步。** 把两条独立线索叠在一起——比如 IP 侧的权利人名单 × 渠道侧的头部卖家名单——能得出单条线索看不出的结论：谁真有资格打我们、谁的壁垒是假的。

**「未找到 / 未核实 / 接口不可达」三档必须严格区分，且报错原文逐字保留。** 缺口清单是交付物的一部分，不是失败自白。概括成「不可用」，下次就无法判断那是临时故障还是永久失效。

**单次抓取只能说结构，不能说趋势。** 这条看起来保守，但「某价位带增长最慢」这类判断一旦没有时序支撑，整个「市场空档」结论就是假的。

**方法本身是交付物。** 数据源可达性表、脚本里的坑，都要落盘——否则每次调研都在重新踩同一批坑。可达性会变，复用前必须重验。

**任务书是输入，不是圣旨。** 调研的职责之一是证伪委托人的假设，不是凑出委托人期待的答案。委托方给的品牌名单、地名、数字都要逐个验证。

## 范围说明

- 适用对象：**新品类 / 新产品的立项决策**。单个 ASIN 快查或已立项品类的月度跟踪用正文末尾的「轻量版」。
- 渠道语境以 Amazon 美国站为主，但七维拆解、四轮节奏、去伪清单、结项门槛与渠道无关，可直接迁移。
- 正文 §8「方法资产化」记录的是**某次调研当时的实测结论**（含各数据源的可用参数、报错原文、限流表现）。**可达性会变，复用前必须逐源重验**；各源的访问方式、速率限制与授权要求以其官方文档和服务条款为准。拿不到数据就按证据纪律记「接口不可达」——这是合格的交付内容。
- 正文 §6、§7、§9 的实例来自实际调研，含真实品牌、案件与成本数字；§14 为试跑教训。**本仓库为内部资料，不对外公开。**
- 文档为中文。
